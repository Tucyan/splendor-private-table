# DeepSeek 基础 / 高级双档与长期记忆优化计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 原版 DeepSeek 完整保留为基础档，独立新增高级档，提供战术分析、局内计划、跨会话经验及每局结束后的同步反思，使用共享文件互斥策略防止经验覆盖。

**Architecture:** 基础档继续调用原有 `src/ai.js`，高级档使用独立入口、上下文、评估和兜底。高级档经验由服务端统一持久化；结束事件先保存反思任务，再生成经验，并在短事务锁内重新读取、合并和原子提交。后续高级对局在同步屏障完成后读取最新经验快照。

**Tech Stack:** 现有 Node.js ESM、node:test、原生文件系统 API、DeepSeek API；不引入数据库或训练服务。

## 1. 已确认范围与兼容约束

- 本文仅为计划，本次不实现或修改游戏逻辑。
- 两档显示名称固定为「DeepSeek · 基础」「DeepSeek · 高级」。用户所说“低级”对应基础档，不新增第三档。
- 原 `mode: 'deepseek'` 继续代表基础档；新增 `mode: 'deepseek-advanced'`。旧请求不带 mode 时仍默认基础档。
- 基础档 `src/ai.js` 文件保持字节不变：system 提示词、上下文、无记忆、模型默认、请求参数、20 秒超时、一次请求、解析、localAction、异常兜底均保持原状。
- 房间调度允许增加分派，但基础分支的调用参数、pending 阶段处理、取消语义均不改变。基础档不读取、不写入、不等待高级经验，也不参与反思。
- 所有优化只属于高级档，包括弃宝石、选贵族、故障回退。不得通过修改共用的 localAction 间接增强基础档。
- 现有本地难度规划是另一条工作线，不能假定 `src/local-ai.js` 中已有可用算法；当前检查发现该文件只有注释，使用前必须重新检查实现和测试。
- 遵守用户执行约束：长时间命令、下载或权限失败最多尝试 3 次；超时后交用户执行，不无限重试；需要下载时优先国内镜像。

## 2. 当前实现依据

- `src/ai.js::buildMessages` 已发送对手宝石，但 opponentGems 与 opponents 分离，未提供身份关联字段与派生威胁。
- 当前明确无历史记忆，thinking 关闭，max_tokens 为 128；高级参数独立配置，基础参数不动。

- `public/app.js` 的邀请弹窗、座位标签与行动状态需识别两个 DeepSeek 档位。

## 3. 高级档决策与信息边界

### 3.1 当前状态和公开观察

将每位对手的 playerId、seat、gems、bonuses、cards、score、nobles、reservedCount 和可观察的预留信息组织在同一对象内。提供目标分数、最终轮、座位顺序、银行库存。

允许记忆从公开市场拿走的预留牌身份，购买后清除对应记录；盲抽只记录等级和数量。自己的预留牌可见。牌堆顺序和对手盲抽身份始终不可见。公开预留知识来自当时的动作和公开市场，不从隐藏手牌反查补全。

### 3.2 程序先计算战术事实

- 每张候选牌折扣后成本、黄金使用、资源缺口、银行可取得性、预计所需行动数。
- 购买后的声望、贵族资格、有效折扣收益、无效囤积和弃筹码代价。
- 对手现在可买的公开牌及已观察预留牌、买后得分、贵族触发、终局威胁与行动先后。
- 区分“达到结束分数”“当前领先”和“最终确定获胜”，遵守末轮补齐与同分少卡。
- 对未知预留牌保留不确定性，不能把“未发现威胁”当成“无威胁”。

### 3.3 局内记忆

按 gameId + playerId 保存主目标、备用目标、贵族目标、预计行动、上轮动作及依据。每回合验证目标是否仍存在、是否可达、是否被更紧急终局威胁取代；事实来自规则引擎，模型计划只是建议。

上下文使用最近事件和压缩摘要，不无限追加聊天。建议初始上限：最近 12 个公开动作、2 个目标、最多 8 条相关跨局经验；分别可配置，并测试截断不丢失关键终局事实。

### 3.4 候选推演与模型选择

从合法动作出发，模拟购买、拿取、预留及后续弃筹码/贵族步骤；先做一步精确评估，再加入有预算的对手回应。不可使用真实隐藏牌堆进行假想补牌；采用未知分支或仅从可观察信息推导的抽样。

模型读取候选事实、短期计划、相关经验，返回合法动作编号和有长度限制的结构化下一步计划。始终用原始 legalActions 取回动作再验证；不能凭模型生成任意动作。高级失败回退到独立战术策略。

高级思考模式、输出预算、温度和超时使用独立配置，接入前核对当时官方 API 支持；先进行延迟和棋力对比，不把打开 thinking 等同于必然提升。

## 4. 跨会话长期记忆与赛后同步

### 4.1 存储内容

默认路径 `data/ai-memory/deepseek-advanced/`，允许用 `DEEPSEEK_ADVANCED_MEMORY_DIR` 覆盖。仅高级档共享通用经验，不为匿名真人建立跨局身份画像。

建议目录：

```text
memory.json                # 权威经验快照及已提交任务标识
memory.previous.json       # 最近一个验证成功的备份
memory.lock/               # 写入互斥目录，含 owner 信息
jobs/<gameId>.json          # 独立、持久化的待反思任务
episodes/<gameId>.json      # 去身份化且按观察者裁剪的对局证据
```

快照 schemaVersion、revision、strategyVersion、updatedAt、processedGameIds、lessons。每条 lesson 包含 id、适用人数/目标分数/阶段、触发条件、建议、反例、证据 gameId、样本数、成功/失败计数、置信度和状态（candidate/active/retired）。不保存密钥、昵称、会话令牌、原始模型内部思维或对手未知牌身份。

经验是可撤回的条件性建议，不是新规则。记录实际发生的结果；未执行动作的效果只能标注为推演，不能伪称已验证。单局结论先为 candidate，反思不允许改源码、规则、system 提示词或自动发布。

### 4.2 结束生命周期

1. 开局分配唯一 gameId，固定本局使用的经验 revision，避免同局策略突然变化。
2. 首次从 playing 进入 finished 时生成不可变结束快照，覆盖真人结束动作、AI 结束动作、连续 pass 和房主主动结束。
3. 对一局多个高级席位生成各自可见的记录，由一项反思任务统一汇总；同一 gameId 只计一次对局，不把席位数量当独立样本。
4. 先持久化任务，再展示反思状态。正常完成可学习胜负；手动提前结束标记 truncated，仅用于局部失误分析，不作正常胜率证据。房间删除/过期的未完成局标记 abandoned，不伪造 finished。
5. 程序计算指标及关键转折，再发一次反思请求，要求有证据引用的结构化经验；输出校验后提交记忆。失败保存本局记录及失败状态，不编造经验、不无限重试。
6. 结束页面显示「经验同步中 / 已保存 / 同步失败」。返回大厅不能删除任务或结束快照。
7. 同步语义：新高级对局开局等待其开始前已经入队的反思任务完成；屏障截止后的新任务不延长本次等待，避免无限饥饿。已有对局和基础对局继续运行。
8. 等待上限建议 60 秒；失败或超时显示清楚的失败状态及“使用上次经验开始”选项，由用户选择降级，不能静默声称已同步。没有密钥时不发反思请求。
9. 重启后加载成功快照并恢复持久化未完成任务；每任务记录尝试数，网络请求和恢复合计最多 3 次。正常单次超时不立即重试；超过上限留待人工处理。

这是通过持久化经验改进推理输入，不是更新 DeepSeek 模型权重。不能承诺每次复盘都提升胜率。

## 5. 共同修改文件的阻塞策略（必须实现）

### 5.1 两层互斥与提交协议

- 同进程所有高级记忆写入走同一 FIFO Promise 队列，禁止各房间直接覆盖 memory.json。
- 跨进程或维护工具以原子 mkdir(memory.lock) 获取独占锁；owner 包含随机 token、pid、hostname、创建时间。初版仅支持同机本地文件系统，不承诺网络共享盘锁语义，也不改变游戏服务单实例限制。
- 锁竞争使用有截止时间的等待，不忙轮询。建议事务锁等待最多 5 秒，超时保留任务并返回明确 memory_busy 状态；不得绕过锁强写。
- DeepSeek 网络反思在锁外执行。持锁期间只做：读取最新版本 → 校验 → gameId 幂等检查 → 合并候选经验 → revision + 1 → 写入同目录唯一临时文件 → flush/close → 原子替换。
- 合并基于锁内最新快照，不用请求开始时的旧快照覆盖；经验和 processedGameIds 在同一份快照提交，避免重复累计。
- 提交成功后才标记任务完成；若快照成功但任务标记失败，恢复通过 processedGameIds 跳过重复学习。
- Windows 替换失败不能先删除旧快照；保留旧数据、临时文件和待处理任务，释放锁并报告失败。
- finally 中只有 token 匹配的持有者可释放锁。不能仅凭锁年龄删除：同机确认 owner 进程不存在后才允许恢复；无法确认则阻塞并提供人工解除指引。
- 读取只接受完整且 schema 校验成功的快照；损坏时使用已验证备份并告警。提交前在锁内维护备份；首次启动无文件可创建空库，损坏文件不可当空库覆盖。
- 清理、归档、手动编辑工具也必须遵守同一锁协议。保留 processedGameIds 幂等索引，不能随普通经验淘汰而遗忘已处理任务。

### 5.2 故障与恢复证明

必须测试两个房间同时结束不丢经验；两个独立 Node 进程竞争同一路径；持锁进程崩溃；进程存活但锁存在时间较长；写临时文件中断；替换失败；损坏 JSON；重复结束通知；提交后未标记任务就崩溃。锁超时不能影响基础档或让服务事件循环阻塞。
